# 正三角形タイリング確認アプリ

依存パッケージ不要の静的Webアプリです。正方形版 `../tiling-checker` のマーク、配色、手、背景、警告、PNG保存、GASアクセス記録を引き継いでいます。正方形版のファイルは変更していません。

## 起動

```sh
python3 -m http.server 8017
```

ブラウザで http://localhost:8017 を開きます。Node.jsがある環境では `npm start`（8000番）も使用できます。

## 操作

- 「ペアにしない辺」で、通常モードのペアを3通りから選択します。
- 半分モードはペアの2辺を分割し、それぞれ同じ辺内でペアを作ります。
- マークなしの辺も独立して分割でき、分割すると追加のペアになります。3～6ピース、1～3ペアです。
- 各ペアにマークと色を指定できます。色は一致判定に影響しません。
- 各ピースのチェックで元の紙片の表裏を設定します。半分ピースは必要に応じて形が合う区間へ移動・交換されます。左右の形の枚数が合わない設定では「組立不可」と表示し、描画・判定・PNG保存を停止します。完成タイルの説明に移動元と移動先を表示します。手はピースの表裏から独立しています。
- タイルをクリックして選択し、同じタイルを再クリックすると120度回転します。Enter・Spaceも使用できます。
- 反転ボタンは鏡映を適用し、全ピースの表裏を入れ替えます。別タイルの初回クリックでは選択だけを行います。
- 外側の余白をクリックすると選択解除します。各リセット・PNG保存に対応しています。

## 幾何と判定

辺長200、中心原点の正三角形を使います。24枚の三角格子に28本の共有辺があります。下向きスロットは `rotate(180)` の配置方向として生成します。上下方向と表裏は独立し、初期配置・全体リセットでは全タイルが表面です。各スロット内の回転は120度、反転は紙面内の鏡映です。格子の上下向きはスロットに固定して隙間を防ぎます。

共有辺の端点を実座標で照合し、分割区間、マーク種類、左右半分、軸方向、共有辺で鏡映した輪郭点を比較します。両方がマークなしなら分割数に関係なく一致します。外周は集計しません。不一致表示を消しても集計は継続します。

表示とPNGは同じSVGから生成し、選択枠だけを保存時に除去します。ピース名や表裏文字はSVGに描きません。保存サイズはタイルが幅1800px、敷き詰めが幅3200pxで、縦横比を維持します。

GASは正方形版と同じURLに `app=triangle-tiling` のGETを文書ごとに1回だけ送ります。失敗・オフライン時は再送せず、描画操作には影響しません。

## 検証

```sh
npm test
```

`node:test` で19群を実行します。全12分割構成、全6剛体変換、表裏、28共有辺の維持、全マークの包含、区間対応と誤りの検出、空白辺、分割変更時の表裏の継承、アクセス記録の一回性を検証します。

ローカルブラウザでは、初期表示、6ピース化、個別表裏、選択、120度回転、反転、手・不一致表示切替、PNG両種のダウンロード、リセットを確認しました。

## 実物の紙の成立条件

半分ピースは30°・60°・90°の不等辺三角形なので、裏返すと反対側の区間の形になります。元のピースごとに表裏を独立して選び、裏返した後の左右の形が同数であるときだけ完成タイルを生成します。表のピースは元の位置を優先し、裏のピースは同じ辺の反対側、それが埋まっていれば他辺の適合する区間に移動します。全ての紙片がちょうど1回使われることと、実際の鏡映・120度回転で輪郭とマークが一致することを全表裏パターンで検証しています。通常の二等辺三角形ピースはその場で裏返せます。

GASへのGET送信契約と失敗時の動作は検証済みですが、GAS側の記録データの保存結果は参照できません。データ保存・自動配置探索・ホスティング公開は今回の実装対象に含めていません。

## アクセス記録の検証

既存の `src/access-counter.js` は正方形版と `app` 名以外同じです。`src/app.js` の初期化末尾から1回だけ呼び出し、操作イベントからは呼び出しません。今回、動作を確認する専用テストを追加しました。

- `tests/access-counter.test.js`：正方形版とのURL・実装照合、GETパラメータとオプション、1回性、再読み込みに相当する新文書、同期・非同期の通信失敗を検証します。正方形版との比較のみ、隣接リポジトリがない環境ではスキップします。
- `tests/access-browser.html`：本番HTMLと本番モジュールをiframeに読み込み、実際の `fetch` 呼び出しを計測します。本番アプリは変更しません。通常は実GASへ送信し、`?fail=1` を付けると通信失敗を模擬します。計測結果はiframeの `html` 要素の `data-access-attempts` 属性に残します。

ローカルブラウザでの結果：初回1回、選択・120度回転・反転・半分モード・マーク変更・手の表示変更・各種リセット・PNG保存後も1回、再読み込みでは新文書から1回。失敗モードでも24枚の描画・回転・反転・設定変更・リセット・PNG保存が動作し、追加送信や未処理エラーはありませんでした。

GASは `no-cors` の応答となり、送信結果から保存行の有無を確認できません。GAS側の保存先・実行ログへのアクセスがないため、サーバー側の記録結果は未確認です。
